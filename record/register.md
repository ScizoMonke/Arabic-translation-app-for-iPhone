# Register

Open flags, risks and surprises. Numbered R1, R2 ... dealt by the orchestrator. Each has an owner or is explicitly declined in decisions.md. Closed entries stay, marked closed with the date and what closed them.

R1 (2026-10-31, open) The PC cannot run the app: no iOS Simulator on Windows. UI verification happens on the user's phone with the user reporting, or on a cloud Mac. Owner: orchestrator; resolves with D8.
R2 (2026-10-31, open) Egyptian dialect is under-served by off-the-shelf speech and translation models, which are mostly trained on Modern Standard Arabic. Real quality on Egyptian speech is unknown until the bench runs real Egyptian audio on this PC. Owner: bench wave.
R3 (2026-10-31, open) No large public corpus of English paired with romanized Egyptian Arabic is known yet. Likely route: generate with a large model, validate a sample with the user's father, distill into something that runs on the phone. Owner: data ledger, then user.

R4 (2026-10-31, open) The web-fetch tool used by ledger agents summarizes pages before quoting; ledger quotes and numbers are not byte-checked against raw pages. Any number a build leans on is re-read from the raw source or measured here first. Owner: orchestrator, applied at every brief.
R5 (2026-10-31, open) No openly licensed Egyptian conversational test audio was found. The bench will measure on the Hugging Face mirror of MGB-3 (MightyStudent/Egyptian-ASR-MGB-3, no license tag) and the ArzEn wav mirror, as private research use for one user. Not redistributed. Owner: bench wave; closes when a licensed source appears or the user accepts the research-use reading.
R6 (2026-10-31, open) Leads for the bottom half from research/ledger/data.md, unverified by download: UBC-NLP/nilechat-arabizi-egy (romanized Egyptian, gated, CC-BY-NC-4.0); MBZUAI-Paris/Egyptian-SFT-Mixture; HeshamHaroon/ArzEn-MultiGenre (25,557 human Egyptian-English pairs, CC-BY-4.0, Arabic script); Mo-Abdalkader Egyptian-English 1M-sentence corpus (origin unstated, probably machine-made); arbml/Arabizi_Transliteration. Owner: next data wave after the on-device model ledger lands.
R7 (2026-10-31, closed same day) The ASR ledger stated WhisperKit's translate task exists "only as server endpoint". Raw source read 2026-10-31 shows DecodingTask.translate in the on-device library. Closed by evidence; R4 stands.
R8 (2026-10-31, open) Nile-Chat's Latin-script training data was generated by Claude, and its paper reports no English-to-Latin-Egyptian evaluation. Quality on our exact task is unmeasured until the PC bench runs. Owner: bench-llm wave.
R9 (2026-10-31, open) SideStore (on-phone refresh without a PC) is reported broken on current iOS: sign-in fixed only in a 2026-09 alpha, refresh failures reported on iOS 26.4 and 27.0.1. AltStore refresh needs a PC on the phone's Wi-Fi. A trip longer than 7 days without a laptop strands the app. Owner: user decision on paid account.
R10 (2026-10-31, open) Foreground app memory ceiling on 12 GB iPhones measured by a third party at about 6144 MB. Whisper large-v3-turbo plus a 4B model at 4-bit must fit under it with headroom. Owner: app wave, measured on the phone.
R11 (2026-10-31, open) GitHub CLI is not installed and no GitHub repository exists for this project. The cloud build cannot start until the user signs in to GitHub on this PC or provides a repository. Owner: user.
R12 (2026-10-31, open) WhisperKit returns only the winning language with no confidence, so routing is binary. The user's accented or short English may be labeled non-English and land in the top half as a forced Arabic translation, producing garbage. Mitigation in place: the Them/Me switch. Real rate is measured only on the phone. Owner: field-test wave.
R13 (2026-10-31, open) First launch on the phone compiles the Core ML model, which can take several minutes, and peak memory sits under the ~6 GB ceiling (R10) with a 4B language model still to add. Both must be done and observed at home before departure. Owner: FIRST_RUN.md and field-test wave.
R14 (2026-10-31, open) Nile-Chat-4B errors observed: left rendered as right (sentence 34), "stop here" as "don't walk here" (36), "I have" as "he has" in Arabizi (38), and a repetition collapse to the token cap (4). Mitigations: phrasebook for the common phrases (D22), back-translated gloss (D20), a repetition penalty in decoding. Owner: bench-llm continuation and app-2.
R15 (2026-10-31, declined) UBC-NLP/NileChat-3B is gated behind a Hugging Face login nobody here holds; not run. Declined because Nile-Chat-4B is chosen (D17).
R16 (2026-10-31, open) The GGUF comes from a third-party quantizer, not the model authors. Its correctness is checked on this PC by running the exact file through Ollama on the 40 sentences and comparing with the bf16 run. Owner: bench-llm continuation.
R17 (2026-10-31, closed by D23) A repetition penalty of 1.15 in llama.cpp breaks the quantized model's JSON. Root cause unproven; the bench's reading is that llama.cpp penalizes the last 64 tokens, including the JSON scaffolding. Shipping without a penalty.
R18 (2026-10-31, open) Quantized two-field prompt still misses on the bench: "good morning" rendered as good evening (row 2), "what does that mean" as what is this (19), "stop here" as garbage (36), feminine first person (39). Rows 2, 19 and 36 are phrasebook entries, which take precedence over the model. Owner: phrasebook-1 must contain them; app-2 prompt carries the gender rule.
R19 (2026-10-31, open) Whisper hallucinations observed on the bench: a show intro translated with a leading profanity, and "subscribe to the channel" on silence or music. The skeleton's Transcriber already drops English marker phrases ("subscribe", "thanks for watching"); it must also drop a leading profanity token and output on near-silent windows. Owner: orchestrator by hand after app-2 merges (Transcriber.swift, marker list).
R20 (2026-10-31, open) The bench audio is broadcast speech (presenters, drama), not a family kitchen with crosstalk and slang; real conversational quality is unmeasured. Mitigation: before departure the user runs the app at home against Egyptian conversational video and reads the top half. Owner: field-test wave.
R21 (2026-10-31, open) qwen3:8b is not a competent judge of Egyptian colloquial; the phrasebook cross-check is weak evidence. The remaining independent checks are Apple's on-phone back-translation of each Arabic line and the user reading glosses in the field. A native ear reading bench/phrasebook/account.md's ten least-certain entries would close this. Owner: user, if a native speaker becomes available.
R22 (2026-10-31, open) Phrasebook gaps noticed in audit: "tant" (طنط), the generic Egyptian word for any aunt or older woman, is absent and would serve him better than choosing a side; "cousin" defaults to the father's side. Short single-word aliases ("what", "here", "left") are untested against the app's fuzzy tier. Owner: field-test wave.
