# Account: wave app-2 (2026-10-31)

Overflow from the return. The bottom half: phrasebook, Nile-Chat-4B on llama.cpp, respelling, Apple gloss.

## Decisions taken in this wave

1. **llama.cpp comes in as upstream's prebuilt xcframework, not as a source package.**
   The brief assumed a Package.swift. There is none at release b12020 (tag commit
   0ec4027a2a0183de87c007069adddc06e665f7de, 2026-10-30). Upstream ships
   `llama-<tag>-xcframework.zip` with every release (built by `build-xcframework.sh macos ios-device`:
   static ggml + llama with Metal and `GGML_METAL_EMBED_LIBRARY=ON`, linked into one dynamic
   `llama.framework`, iOS minimum 16.4, ios-arm64 + macOS slices, no simulator slice).
   `docs/xcframework.md` shows the SwiftPM `binaryTarget(url:checksum:)` pattern. So
   `app/LlamaBinary/Package.swift` is a local package with one binaryTarget named `llama`
   (the framework's module name), wired in `project.yml` as a local package.
   - Checksum `78fdf6ec32fad1f0e55a3fd78401841ba0a7b34f26b30078c6dc8d7951d81ae5`: SHA-256 of
     the zip downloaded here, equal to the digest GitHub lists for the asset.
   - Zip layout `build-apple/llama.xcframework/...`: SwiftPM release/6.2
     `Workspace+BinaryArtifacts.swift` (`shouldStripFirstLevel`, `deriveBinaryArtifacts`) strips a
     single top folder whose child is an `.xcframework`, then searches recursively. Read in source.
   - The header inside the zip is byte-identical to `include/llama.h` at the tag.
   - Effect: no ggml compile on the runner, so the build barely lengthens (one 70 MB download).
     Timeout raised 60 -> 75 min anyway.
   - Fallback if the binary target fights Xcode: the same xcframework fetched by a workflow step
     and referenced as an XcodeGen `framework:` dependency (embed: true). MLX Swift (D21
     fallback) was NOT needed and is not built; see the end of this file for what it would take.

2. **GGUF pinned by repo commit, verified by size and SHA-256.**
   `https://huggingface.co/mradermacher/Nile-Chat-4B-GGUF/resolve/3e4cf41e8a0cd6292831f09afef27644125c26fa/Nile-Chat-4B.Q4_K_M.gguf`,
   2,489,894,752 bytes, sha256 `9ab2de4f11195f5cb0e106403cf20a39785728aa12d9418b7a939b6df27e61d2`
   (HF API `?blobs=true`; `X-Linked-Size` agrees). Download: own URLSession data task into a
   `.part` file, HTTP Range resume (survives app restarts), Wi-Fi only
   (`allowsCellularAccess = false`, D9), 206 must start at the `.part` size, size + SHA-256 before
   the rename. Whisper's download is still WhisperKit's own (unchanged).

3. **GGUF metadata read from the file header here (first 24 MB by Range request):**
   `general.architecture = gemma3`, 34 blocks, sliding window 1024, vocab 262,208,
   `tokenizer.ggml.add_bos_token = False`, chat template = Gemma 3 (system folded into first user
   turn as `system + "\n\n"`, user content trimmed, `<start_of_turn>model\n` generation prompt).
   Consequence: the tokenizer will not add `<bos>`; LlamaEngine prepends `llama_vocab_bos` by hand
   and tokenizes with `parse_special = true` so the turn markers are control tokens.

4. **Prompt and template.** `NileChatPrompt.instruction` is bench prompt C copied byte for byte
   from `runs/Nile-Chat-4B-promptC-rp1.15/meta.json` (generated by script, not retyped), plus the
   two D24 rules inserted before the examples. `render(english:)` reproduces the bench's
   `first_prompt_rendered` exactly (checked by a Python mirror: identical apart from `<bos>`,
   which is a token). Swap: replace the raw-string body of `instruction`.

5. **Decoding per D23** (amended mid-wave by the orchestrator): greedy, no repetition penalty,
   n_ctx 2048, at most 120 new tokens, stop at an EOG token / `<end_of_turn>` / the first closed
   top-level JSON object (string-aware byte scan) / the loop guard (trailing run of one character
   longer than 8). Retry once with top_k 20, temperature 0.3, dist seed 1234 (fixed so a retry is
   reproducible). KV cache cleared per sentence. `load_mode = LLAMA_LOAD_MODE_MMAP` explicitly
   (in b12020 `use_mmap` no longer exists; it became the `load_mode` enum), all layers on Metal.

6. **Validation per D24**: arabic field must contain Arabic-range letters and no ASCII Latin
   letters; arabizi none of the Arabic range. Added by me: arabizi must contain at least one Latin
   letter (otherwise the respelling is digits and punctuation). After two failures: rough
   letter-by-letter transliteration of the last Arabic field that had letters (one Cairene
   consonant map: j as g, q as apostrophe, th as t, dh as z; vowel marks dropped), tagged
   `model, ROUGH: letters only, vowels missing`; if none, "the model could not answer".
   The gloss for a rough card is still Apple's translation of the Arabic.

7. **Gloss provenance**: only `AppleTranslator.toEnglish` (Apple Translation ar -> en) or the
   phrasebook entry's vetted gloss. If the pack is not installed: "Meaning check unavailable: ...
   Tap the gear ...". If installed but translation fails: "Meaning check failed for this one. Do
   not rely on it." The model's text never reaches the gloss line.

8. **Phrasebook matching** as dealt (normalize; exact alias; else best word-set Jaccard >= 0.75)
   **plus a guard I added**: a close match is refused when the two word sets differ in a
   meaning-flipping word (negations, left/right, before/after, more/less, time words, pronouns,
   number words). Reason: the dealt rule matches "I don't want tea" to "I want tea" (Jaccard 0.75)
   and "please turn left at the next street now" to the "right" version (0.78). A close match also
   shows the alias it matched in its tag, so he can see the difference. Normalize removes
   apostrophes (so "don't" = "dont") and turns other punctuation into spaces.

9. **Two queues.** Whisper keeps its single utterance queue; his own sentences then go into a
   second AsyncStream consumed by the Egyptian model, so the top half never waits on a
   generation. LlamaEngine runs every C call on its own serial DispatchQueue (not an actor), so a
   several-second generation does not occupy a Swift cooperative thread Whisper needs.

10. **Loading order and memory**: Whisper load, MEM line, phrasebook, MEM line before the LLM,
    LLM load, MEM line. One MEM line after every utterance (`phys_footprint`,
    `ledger_phys_footprint_peak`, resident, peak resident, `os_proc_available_memory`).
    A UserDefaults marker set around the LLM load: if iOS killed the app during that load, the
    next launch skips the LLM once (status line says so) so the top half stays usable; the launch
    after retries. A failed LLM load opens the app anyway with an explanatory status.

11. **Logging**: the card's log line equals the screen (heard | say | gloss line | [source]).
    Diagnostics (timings, stop reasons, rejection reasons, raw model text on failure) go below it
    as `  diag:` lines. Raw text has Arabic-range code points escaped as `\u{XXXX}`
    (`ScriptGuard.escapeForLog`), so D5 holds even in the log file and the text is recoverable.

## Flags

Build, by likelihood:
1. Dynamic `llama.framework` from a SwiftPM binary target not embedded into the .app (dyld crash at
   launch). The workflow now fails the run if `EgyptTalk.app/Frameworks/llama.framework/llama` is
   missing. Fix path in FIRST_RUN 2.0.
2. A Swift 6.2 diagnostic I did not anticipate around `@unchecked Sendable` classes or the
   `@Sendable` closures (Swift 5 mode keeps most as warnings).
3. The binary artifact location for the informational resolve check (warning only, not a gate).

Runtime:
- Memory: Gemma 3 4B Q4_K_M weights 2.49 GB + KV for 2048 tokens (about 0.3 GB, less with SWA)
  + compute buffers (unmeasured) + Whisper large-v3. Whether Metal's no-copy buffers over the
  mmap count in `phys_footprint` on iOS is not known here; the MEM line will show it.
- No `com.apple.developer.kernel.increased-memory-limit` entitlement: a free Apple ID through
  AltStore is unlikely to carry it; not added.
- `AppleTranslator` is an actor whose `toEnglish` awaits inside; the top-half fallback and the
  gloss can now interleave two `translate` calls on one TranslationSession. Untested whether the
  session tolerates that.
- "Where is the bathroom" is not yet in the sibling's phrasebook (88 entries in its worktree at
  commit 04cfbd2); the FIRST_RUN phrasebook check depends on it being added.
- llama.cpp writes its own log to stderr (not captured in the session log).

Skeleton (noticed, not fixed):
- Whisper's download (WhisperKit/Hub) may use mobile data; only the GGUF download is Wi-Fi-only.
- `TranslationPackSection`'s doc comment still calls the pack an optional backup (the UI text was
  updated; the comment is cosmetic).

Housekeeping outside the worktree (mine, removable): `C:\VScode\a2e-wt\_src\llama.cpp-b12020`
(shallow clone), `C:\VScode\a2e-wt\_data\xcf-b12020` (70 MB zip), `_data\hf` (24 MB GGUF head +
API JSON), `_data\spm`, `_data\xcodegen`. Not deleted.

## MLX Swift fallback (D21), described only

maps `gemma3_text` to Gemma3TextModel, per the bench account). Needs an MLX-format 4-bit

download spec, and a different engine file behind the same `EgyptianRomanizer` calls
(`engine.load` / `engine.generate`). Prompt, parser, respelling, gloss and phrasebook are unchanged.
